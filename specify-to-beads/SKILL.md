# Specify-to-Beads

Converts a completed the-startup specification into a Beads (`bd`) epic with tasks and inter-phase dependencies — creating a living, source-controlled task graph that outlasts the spec itself.

Read [references/workflow.md](references/workflow.md) before executing.

## When to Activate

- User runs `/specify-to-beads` explicitly
- User says "load the spec into beads", "import spec to beads", "sync spec to bd"
- User has just finished `/specify` and wants to track execution in Beads

## Quick Reference

```
Spec location:  .start/specs/<NNN>-<slug>/
Epic:           one per spec
Tasks:          one per phase (phase-1.md → task, phase-2.md → task, etc.)
Dependencies:   each phase blocks the next (sequential by default)
Labels:         spec-<NNN>, phase-<N>
Source link:    bd comment <id> with path to spec file
```

## Execution Steps

### 1. Preflight — Check bd is available and initialized

```bash
bd --version
bd ready --json 2>/dev/null | head -1
```

If `bd` is not found: stop and tell the user to install Beads first:
`curl -fsSL https://raw.githubusercontent.com/steveyegge/beads/main/scripts/install.sh | bash`
then `bd init` in the project root.

### 2. Resolve the spec to load

**If the user provided a spec number or slug** (e.g. `/specify-to-beads 001` or `/specify-to-beads auth`):
- Look for `.start/specs/<NNN>-*/` matching the argument.

**If no argument:**
- List all specs: `ls .start/specs/`
- If only one exists, use it automatically.
- If multiple exist, list them and ask the user which to load.

### 3. Read the spec

Read these files from the resolved spec directory:
- `requirements.md` — what and why (used for epic description)
- `solution.md` — how (used for task descriptions)
- `plan/README.md` — phase manifest and ordering
- `plan/phase-*.md` — one file per phase; each becomes one Beads task

Parse each `phase-N.md` to extract:
- **Title**: first `#` heading or filename fallback (`Phase N`)
- **Description**: summary paragraph after the heading (first 3-5 sentences)
- **Tasks/checklist items**: any `- [ ]` lines (include in bd task description)

### 4. Create the epic

```bash
EPIC_ID=$(bd create "<spec-slug>: <one-line summary from requirements.md>" \
  -t epic \
  -p 1 \
  --description "<2-3 sentence summary of requirements.md>" \
  --label "spec-<NNN>" \
  --json | jq -r '.id')
echo "Epic: $EPIC_ID"
```

Immediately annotate it with the spec path:
```bash
bd comment $EPIC_ID "Source spec: .start/specs/<NNN>-<slug>/ — generated by /specify-to-beads"
```

### 5. Create phase tasks (children of the epic)

For each `phase-N.md` in order:

```bash
TASK_ID=$(bd create "Phase N: <phase title>" \
  -t task \
  -p 1 \
  --description "<phase summary>\n\nChecklist:\n<- [ ] items from phase-N.md>" \
  --label "spec-<NNN>,phase-<N>" \
  --json | jq -r '.id')

# Link as child of epic
bd dep add $TASK_ID $EPIC_ID --type parent-child

# Link to previous phase (sequential blocking)
# (skip for phase 1)
bd dep add $TASK_ID $PREV_TASK_ID --type blocks
```

Annotate each task with its source file:
```bash
bd comment $TASK_ID "Source: .start/specs/<NNN>-<slug>/plan/phase-N.md"
```

### 6. Print summary

After all tasks are created, run:
```bash
bd show $EPIC_ID
bd dep tree $EPIC_ID
```

Then tell the user:
- How many tasks were created
- The epic ID and its children
- That the spec files in `.start/specs/<NNN>-*/` can now be treated as reference-only
- Remind them to commit `.beads/` alongside their code: `git add .beads/ && git commit -m "chore: load spec <NNN> into beads"`

### 7. Suggest spec retirement (non-destructive)

Say to the user:

> The spec files in `.start/specs/<NNN>-<slug>/` are now loaded into Beads. Once implementation is underway and Beads becomes the source of truth, you can safely delete the spec directory (`rm -rf .start/specs/<NNN>-<slug>/`) or move it to `.start/specs/archive/`. The task history in `.beads/` will survive.

Do NOT delete the spec files automatically — always leave this to the user.

## Error Handling

| Problem | Action |
|---|---|
| `bd` not found | Stop, show install command |
| `.start/specs/` not found | Stop, tell user to run `/specify` first |
| No `plan/` directory in spec | Warn, create one epic task from `requirements.md` only |
| Phase file has no `#` heading | Use filename as title (`Phase N`) |
| `bd create` fails | Show the error, stop, do not continue silently |

## Important Rules

- Never delete spec files — only suggest the user does so
- Never create duplicate epics — check `bd list --label spec-<NNN> --json` first; if results exist, warn and stop
- Always use `--json` on bd commands and parse with `jq` for reliable ID extraction
- Commit reminder is mandatory — `.beads/` changes must be committed or they won't survive context resets
